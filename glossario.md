# Glossário

| Termo | Significado |
|---|---|
| **Acoplamento** | Grau de dependência entre módulos. Preferir contratos explícitos e dados necessários. |
| **Adaptador** | Componente que converte uma interface própria para a API de outra implementação. |
| **Coesão** | Relação entre os elementos de um módulo e seu propósito único. |
| **Code smell** | Sinal de que a estrutura pode dificultar mudanças; não é, por si só, prova de defeito. |
| **DIP** | Princípio de inversão de dependência: políticas e detalhes dependem de abstrações. |
| **DI** | Injeção de dependência: fornecer dependências a um objeto, em vez de instanciá-las dentro dele. |
| **Interface estável** | Contrato que permite mudar implementação sem exigir mudanças nos clientes. |
| **LSP** | Subtipos podem substituir seus tipos base sem quebrar as garantias esperadas. |
| **Módulo** | Unidade de organização relativamente independente, como classe, pacote ou componente. |
| **OCP** | Aberto para extensão e fechado para modificação. |
| **Ocultamento de informação** | Esconder decisões e detalhes que podem mudar atrás de uma interface. |
| **Refatoração** | Alteração estrutural que preserva o comportamento observável. |
| **Reuso responsável** | Reaproveitar sem espalhar decisões de bibliotecas ou responsabilidades inadequadas. |
| **SRP** | Uma classe deve ter um único motivo de mudança. |
| **ISP** | Clientes não devem depender de métodos que não utilizam. |
| **Strategy** | Padrão que encapsula variações de um algoritmo em implementações substituíveis. |
